# InterviewAI — Project Requirements

## Overview

**InterviewAI** is a web platform that allows users to practice and take AI-powered mock interviews for various job roles. It uses a VAPI voice agent to conduct the interview, Groq to summarize the transcript into structured Q&A, and Supabase for data persistence and authentication. The frontend is built with Next.js and TypeScript.

---

## Tech Stack

| Layer | Technology |
|---|---|
| Frontend | Next.js 14+ (App Router), TypeScript |
| Backend / Database | Supabase (PostgreSQL + Auth + Storage) |
| Voice Interview Agent | VAPI |
| Transcript Summarization | Groq API (LLaMA 3) |
| Styling | Tailwind CSS |

## Pages & Routes

### 1. Landing Page `/`
- Hero section with product tagline and CTA ("Start Practicing")
- Brief feature highlights (voice AI interviews, job marketplace, interview history)
- Clean footer with links
- No authentication required to view

### 2. Authentication `/auth`
- Sign Up and Sign In on the same page (toggled via tab)
- Fields: Full Name (sign up only), Email, Password
- Auth handled via **Supabase Auth** (email + password)
- On successful sign-up, a row is inserted into the `users` table in Supabase
- Redirect to `/dashboard` on success

### 3. Dashboard `/dashboard`
- Protected route — redirect to `/auth` if not authenticated
- Persistent sidebar + top header layout

## Dashboard Layout

### Top Header
- App logo / name on the left
- User avatar + email on the right
- **Logout button** that calls `supabase.auth.signOut()` and redirects to `/`

### Sidebar Navigation
Three primary tabs:

#### 1. Start Interview
- User selects a job role (carried over from the Jobs tab or freshly selected)
- A "Begin Interview" button triggers the VAPI call
- VAPI call is initialized with:
  - `company_name` (from selected job)
  - `role` (from selected job)
  - `candidate_name` (from user profile)
  - `job_description` (from selected job)
  - `interview_focus` (default: "mixed")
- During the call, a minimal in-call UI is shown (waveform / speaking indicator, timer, end call button)
- On call end, VAPI sends back the full transcript
- The transcript is immediately sent to the **Groq API** for summarization

#### 2. History
- Displays a list of all past interviews for the logged-in user
- Each entry shows:
  - Job role and company name
  - Date and duration
  - Status badge (Completed)
- Clicking an entry opens a detail view showing the **structured Q&A summary** generated by Groq
- Q&A is displayed as an accordion or card list: Question → Answer pairs

#### 3. Apply for Jobs (Marketplace)
- A grid/list of available job interview templates
- Each job card shows:
  - Job title
  - Company name (or "Generic")
  - Domain/category (e.g., Engineering, Design, Marketing, Product, Data, Sales)
  - Difficulty level (Junior / Mid / Senior)
  - Short description
- Clicking a job card → navigates to **Start Interview** tab with that job pre-selected
- Jobs are stored in Supabase `jobs` table and seeded with a variety of roles

## Supabase Database Schema

### `users`
```sql
create table users (
  id uuid primary key references auth.users(id) on delete cascade,
  full_name text,
  email text unique not null,
  avatar_url text,
  created_at timestamp with time zone default now()
);
```

### `jobs`
```sql
create table jobs (
  id uuid primary key default gen_random_uuid(),
  title text not null,
  company_name text default 'Generic',
  category text not null,
  difficulty text check (difficulty in ('Junior', 'Mid', 'Senior')) not null,
  description text,
  job_description text not null,
  interview_focus text default 'mixed',
  created_at timestamp with time zone default now()
);
```

### `interviews`
```sql
create table interviews (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references users(id) on delete cascade,
  job_id uuid references jobs(id) on delete set null,
  role text not null,
  company_name text,
  vapi_call_id text,
  raw_transcript text,
  duration_seconds integer,
  status text default 'completed',
  created_at timestamp with time zone default now()
);
```

### `interview_summaries`
```sql
create table interview_summaries (
  id uuid primary key default gen_random_uuid(),
  interview_id uuid references interviews(id) on delete cascade,
  qa_pairs jsonb not null,
  -- Structure: [{ "question": "...", "answer": "...", "score": "strong|adequate|weak" }]
  overall_summary text,
  created_at timestamp with time zone default now()
);
```

## VAPI Integration

### Flow
1. User clicks "Begin Interview" on the Start Interview tab
2. Frontend initializes VAPI Web SDK with the system prompt and injected runtime variables
3. VAPI conducts the voice interview with the Alex agent
4. On call end, VAPI fires a `call-end` webhook/event containing the full transcript
5. Frontend (or a Supabase Edge Function) receives the transcript

### VAPI Variables Injected at Runtime
```json
{
  "company_name": "...",
  "role": "...",
  "candidate_name": "...",
  "job_description": "...",
  "interview_focus": "mixed"
}
```

## Groq Integration (Transcript Summarization)

### Trigger
Called immediately after VAPI returns the transcript on call end.

### Endpoint
`POST https://api.groq.com/openai/v1/chat/completions`
Model: `llama3-70b-8192`

### Prompt Sent to Groq
```
You are an expert interview analyst. Below is a raw transcript of a voice interview between an AI interviewer (Alex) and a job candidate.

Your task is to extract every question asked by Alex and the corresponding answer given by the candidate. Return ONLY a valid JSON array with no extra text, markdown, or explanation.

Format:
[
  {
    "question": "...",
    "answer": "...",
    "score": "strong | adequate | weak"
  }
]

Score each answer:
- "strong" if the candidate gave a confident, detailed, and relevant answer
- "adequate" if the answer was acceptable but lacked depth
- "weak" if the candidate struggled, gave a very short answer, or said they didn't know

Also append a final object with key "overall_summary" containing a 2-3 sentence summary of the candidate's overall performance.

Transcript:
{{raw_transcript}}
```

### On Success
- Parse the JSON response
- Save to `interview_summaries` table with the `interview_id` foreign key
- Display in the History tab detail view

## Key User Flows

### New User
1. Lands on `/` → reads about the product
2. Clicks "Get Started" → goes to `/auth`
3. Signs up → row created in `users` table → redirected to `/dashboard`
4. Explores Jobs tab → picks a role → goes to Start Interview
5. Completes interview → Groq summarizes → saved to DB
6. Views Q&A in History tab

### Returning User
1. Visits `/auth` → signs in → redirected to `/dashboard`
2. Views past interviews in History tab
3. Starts a new interview from Jobs tab or Start Interview tab

## Non-Functional Requirements

- All routes under `/dashboard` are server-side protected (middleware redirect)
- Supabase Row Level Security (RLS) enabled on all tables — users can only read/write their own data
- Groq summarization happens client-side or via a lightweight API route (`/api/summarize`) to keep the API key server-side
- VAPI transcript webhook should be handled via `/api/vapi/webhook` route
- Mobile-responsive layout
- No hardcoded question lists anywhere in the system — all interview questions are dynamically generated by the VAPI agent at runtime based on candidate responses
